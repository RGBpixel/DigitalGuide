## 当前可操作流程

- 顾客就餐实际结束后出现感谢与两个独立表单。评分可不选，评价和回访均可跳过；没有默认勾选、自动评价或自动回访。
- 评价按当前就餐、访问、发问人、选择与评价版本确认。修改输入、评分、处理方式或版本后必须重新核对。其他终端更新评价时保留未发送草稿，显示差异并要求载入当前记录。
- 回访单独填写电话或邮箱、明确visit_followup用途及1、7、14或30天期限。保存成功后清空完整联系值，界面仅显示掩码。修改联系类型、输入或期限会取消原确认。
- 撤回先选择对应操作，再勾选该项清除确认。撤回评价不取消回访；撤回回访不删除评价。服务端继续执行当前归属、版本、幂等和权限检查。
- 顾客可展开并自行复制本项撤回凭证，或打开`/aftercare/manage`独立页面。凭证由本人粘贴到POST正文，不进入链接、URL、历史状态或页面本地存储。独立入口无需原终端在线，不登录、不读取私人正文、不取得业务权限。
- 店员看板只展示本店自愿评价与回访掩码，不提供本人凭证或代客授权入口。主动核对或轮询发现职责失效后清除旧数据；被取消的迟到读取不能恢复旧看板。
- 转人工、换人或终端结束后不显示上一位的评价、掩码或凭证。迟到读取被取消，表单不保留旧确认。返回自动模式后需明确选择本人记录并重新核对。

## 已结束记录的选择修复

原界面与服务端只允许选择仍在就餐中的组，导致结束后的记录在切换组或转人工后不能继续自愿评价。追加121，仅在既有`select`分支允许本人已完成的组；原会话、CSRF、选择代次、发问人、归属和就餐版本校验保持。取消或未到店记录仍拒绝重新选择。

选择只改变当前咨询对象，不重开就餐、占座、期限、凭证、库存、订单或资金权限。实际用例验证本人可选回并评价，其他终端被拒绝，旧版本/旧选择/旧发问人和人工状态被拒绝，结束记录不能继续点单、改偏好或转移就餐凭证。121首次提交后冻结；001—121/runtime118，下一122。SQLite052/下一053保持。
