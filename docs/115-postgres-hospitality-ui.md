沿[T20餐中服务后端](114-postgres-hospitality-services.md)继续R-003、R-035、R-047—R-052。当前接通本人手工服务请求、本店员工队列和已结束记录的界面，独立原生mock版本默认开放serviceRequests。完整hospitality仍为false；对话服务建议、餐后评价/独立回访和主动迎宾保持后续目标。视频/PPT、直播、发布投放、展厅、企业前台、餐厅、真人形象克隆、声音与语气等完整平台范围保持。

## 当前行为

- 顾客可选择加水、餐巾纸、店员帮助、菜品进度或结账协助，核对说明后明确提交；可取消本人的待处理请求。顾客界面没有店员接收或确认完成选项。
- 本店迎宾/经理可在餐中服务队列或本组详情选择处理方式，再明确确认并提交。接收与完成分开确认；操作方式、请求版本、就餐版本、归属、发问人或当前选择变化后，旧勾选失效。
- 本组安排变化会使旧提交确认失效，同时保留当前未发送说明；切换顾客、人工交接或凭证转移时不会把旧确认和私有说明带给另一组。人工模式显示只读记录，恢复后需要重新核对。
- 读取与操作被拒绝时清空私有服务记录并提供重读入口；取消旧读取。换人、恢复凭证和撤销员工职责后，迟到的原授权响应不能重新显示旧服务说明。
- 支持查看已处理及随就餐结束关闭的历史。正常就餐结束后，本人和员工仍可查看服务记录，顾客不能新建或处理已结束服务；餐后评价和回访表单仍不开放。
- serviceRequests与完整hospitality分开表达。原生mock的新构建默认具备餐中服务；不把服务队列当作已完成主动迎宾、评价、回访或真实外部通知。
