# 原生点单、账单与员工界面阶段

沿T20接续[原生收款退款](111-postgres-financial.md)，覆盖R-048点单、R-049后厨、R-050账单及R-052当前用途授权。完整视频/PPT、直播、发布投放、展厅、前台、餐厅、真人形象克隆、声音与语气复刻及全部竞品目标保持。

已接通原生mock环境中的员工点单、历史订单、独立结算及历史退款界面。访客端、权限撤回、发问人/选择切换及手机浏览器验收仍在进行；nativeOrderUiVerified=false，对应默认ordering/payments标志保持关闭，hospitality=false。独立开发预览可以明确启用，不代表已通过完整餐厅或真实业务验收。

已实现：

- 当前权限读取传入取消信号，读取失败时隐藏原私有数据；401/403/404后取消旧读取，再重新获取。相关界面已接入此防护，撤权与迟到响应的完整浏览器验证仍待完成。
- 点单与账单勾选绑定当前对象、版本、发问人/选择、审阅摘要和连接；远端修订或本地未保存输入使原确认失效。退款审阅与最终执行分别确认，创建收银入口仍为未付款，模拟付款需要再次明确确认。
- 服务端提供同组至多100单历史。已付款但尚未上菜时，可以创建新的独立订单；原单资金及后厨制作保留，新旧订单分开审阅和结算。同组仍至多一份未结算有效订单，并发创建返回明确冲突。
- 员工可查看旧单、返回当前未结订单；账单列出独立原请求、未知退款预留、原请求查询、模拟收据及经理历史退款。收款与上菜分别核对，全部完成后才可结束就餐。
- 下载前核对当前目标及账单版本，变更目标后的旧下载结果不直接交付；此实现还需补齐对应浏览器切换验证。匿名来客、声纹和人脸候选不获得订单或退款操作身份。
