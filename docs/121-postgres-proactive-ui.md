# 本次主动问候设置与顾客界面

沿[主动问候用途后端](120-postgres-proactive-consent.md)继续T20和R-003、R-035、R-047、R-051、R-052、R-129、R-131、R-132。新原生mock餐厅终端提供本次用途、免打扰、静默、冷却及公开称呼设置，明确区分偏好保存、公开称呼授权和本次主动交流。

全部134项需求、38任务、65验收及26能力组保持。视频/PPT、多轨与模板、多人同屏、批量协作、4K与透明导出、资产迁移、直播与多平台发布投放、展厅、前台、餐厅以及真人形象、声音和语气均保留在最终目标中。27/38仅为本地任务数比例。

## 顾客操作

“本次主动问候”默认关闭。顾客可以开启本次问候、选择免打扰、设置门店时区下的静默开始/结束时间及5—1440分钟冷却，另行选择是否使用本人已经确认的公开称呼。相同的静默开始和结束表示全天静默。保存必须由本人再次核对并勾选当前设置。

界面显示当前是否已有本次用途同意、无法主动问候的原因、原到期时间和最近一次问候。免打扰、静默、冷却、交流繁忙和门店暂停均有明确说明。缺少公开称呼的独立记忆授权时，保存明确失败并指引先管理“我的接待偏好”，不会悄悄改成普通问候并显示成功。

已生效的本次用途有直接撤回入口。撤回不依赖尚未保存的草稿，也不需要重新允许使用公开称呼；它不会删除本人单独保存的偏好。撤回后取消相应问候记录；页面观察到播放记录取消时，立即清除本机模拟播放计时器和演示状态。当前没有真实声音合成，不把此演示当作实际扬声器或数字人SDK中止验收。

## 草稿、确认与隐私

确认绑定当前会话、发问人、回复代次、就餐选择、用途版本、接待版本及本地输入。任一输入改变都会清除旧勾选。后台设置被其他有效操作更新时，本地草稿保留，保存按钮禁用，顾客需明确载入当前设置并重新核对。

提交前读取当前用途。若版本、发问人或就餐选择发生变化，不自动把旧确认升级为新确认。读取阶段遇到换人或转人工会终止旧读取；已经发出的写入由服务端按原范围判断。迟到结果不能覆盖更新的状态，也不能带到另一位顾客或另一组。

换组或发问人变化后，原设置草稿不跟随到新对象，新表单使用当前范围的设置或关闭默认值。转人工时不显示可操作表单。401、403或404会清除本次用途和接待查询；被暂存的旧授权读取不能恢复私人界面。组件卸载后不保留本次用途查询缓存。

新原生餐厅通过可选`proactiveGreetings`能力字段显示该面板；既有SQLite和企业前台不因此出现未连接的餐厅入口。该能力字段描述可用界面，完整hospitality及全平台G2仍分别验收。本增量没有新增应用SQL；001—124/runtime121冻结，下一125；SQLite052/下一053保持。

本批浏览器验证覆盖默认与输入确认、持久免打扰、后台更新与草稿保护、撤回播放演示、原五分钟冷却、公开称呼的独立授权、390px手机操作、暂存原POST、迟到预检、换组、撤权与重启。各阶段实际通过数量、失败和接续记录以[界面检查点](evidence/T20/postgres-proactive-ui/ui-checkpoint.json)为准；完整文件摘要归档于`docs/evidence/T20/postgres-proactive-ui/verification.json`。

自然冷却检查使用本批新问候自己的原五分钟期限。等待期间用明确的合成顾客交流保持原访次有效，保留原会话标识、发问人和最大截止时间，不恢复过期会话，也不修改客户端/服务端时钟。它不重复前一批已封存的期限生产器。

首轮先通过四项界面流程，模拟播放在撤回后于原三秒演示计时结束前失效。随后第二次受控在场消息已经提交，但验证脚本用相同文字定位时匹配到两条消息而失败；该失败及原两条消息保留，没有重复提交。独立核对进程关闭后，原访次已按其120秒闲置期限自然过期。接续保持同一原数据库、两密钥和78份编译文件，明确建立新访次，使用新问候自己的原五分钟期限继续未完成的自然冷却验证；不恢复旧访次，不重做早先四项已通过界面流程。接续在场消息使用不同序号，避免观察器重复文本匹配。

原五分钟检查随后完成，实际间隔300550ms，同一访次、发问人、最大期限及续验同意行保持。公开称呼与手机保存也通过，达到七项流程。后续暂存写入脚本误把同一路径的GET预检当作POST解析，写入尚未发出；失败记录保留。再次独立关闭后，只对剩余五项续验，原自然冷却、公开称呼和手机保存均不重复。原第二终端已自然闲置过期，明确新访次只准备独立合成本人资料以验证清屏，不恢复原资料或原权限。

合计12个不同GUI按4+3+5分阶段有通过证据，另2项来源/旧凭证回归通过；当前类型、lint、构建与OpenAPI检查结果随检查点归档。390px主动问候卡片已视觉复核，保存按钮命中及整页无横向溢出有实际断言。492表、原两密钥和78份编译文件在API与PG重启后保持；旧场景访问仍拒绝。严格关闭2根、11端口和85个已捕获创建身份，私有进程/监听为0，不扩大单元夹具PID时间覆盖。主33223原四进程、301表3318原行/3310业务行、原两密钥和AE配置保持，不重启切库。

## 启动与使用

现有[主工作台5174](http://127.0.0.1:5174)保持原版本、数据库、两类密钥和AE配置，不重启切库。按[独立原生启动说明](62-postgres-native-core.md)使用当前构建、runtime121和124迁移建立新的development/mock实例，并启动同一实例的worker；不要启动已封存证据根或替换原库。

在本店顾客终端打开“本次主动问候”，核对需要的时段与冷却，勾选当前用途并保存。普通问候无需登记长期人员资料；公开称呼需先在“我的接待偏好”自愿登记、允许个性化，并确认可供接待使用的nickname。已有免打扰、静默和冷却继续生效。随时可撤回本次主动问候。

本轮不宣称已经具备摄像头自动发现来客、真实身份识别、实际声纹/ASR或真人驱动。真实形象/声音/语气、现场设备和业务渠道接入、长期运行、生产保留与恢复后删除，以及全部原始平台G2继续建设。完整hospitality=false，T20和开发目标保持进行中。
