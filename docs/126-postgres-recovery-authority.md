# 恢复后的保守撤权与多步骤操作衔接

2026-11-26｜增量126｜R-009、R-053、R-054、R-058、R-059；T20、AC-27、G2继续。

本轮使恢复副本能够按最新签名日志与固定预览，撤下变化后的旧成员权限、对应素材用途和变动素材访问。它与既有个人资料清理共用受锁保护的完整目标摘要，并用不可变运维收据证明多步操作后的状态延续。当前身份、完整权限与生产启用仍需另行核对。

## 实现与边界

| 日志匹配对象 | 恢复副本上的保守处理 | 保留与限制 |
| --- | --- | --- |
| memberships 或 users | 匹配旧成员降为 viewer，工作空间列表清空 | 不补发任何权限；不把人脸或声纹候选当成登录身份 |
| consents | 撤销匹配的旧专项授权 | 同一素材的其他独立用途不因该条变化自动撤销 |
| assets | 匹配旧素材归档、版本递增、保存完整素材历史快照，撤销其旧授权 | 归档通过现有关联规则使失效任务停止；不下载、迁移或激活真实模型 |
| auth_sessions | 全部恢复旧登录失效 | 不将备份中的登录继续当成当前身份 |

选择只使用既定表和主键、签名包中的带盐旧/新主键摘要及 TRUNCATE 标记，不执行包内代码或任意清理表名。未覆盖的变更类别仍明确列出，计划保持 pending。预览不写业务表或创建永久运维表；确认必须绑定最新计划和完整目标摘要。提交前锁定原生表，重新核对隔离策略、日志基线、最新计划和目录摘要。

撤权先处理冻结的授权集合，再归档素材。归档已有自动撤销规则，因此不能随后覆写其不可变撤销时间。成员、授权、素材、版本历史、登录、关联失效和本次收据在同一事务中提交；异常回滚全部效果。

SQL128 只为形象任务的纯依赖检查增加所有者、隔离状态、真实待处理计划和本事务编号共同限定的上下文，防止隔离副本中一次局部变更使无关任务全部失效。它不改变运行状态或授予 API/worker 连接与执行能力。001—128/runtime125在首次提交后冻结，下一129；SQLite052/下一053保持。

两类业务效果收据和运维状态边放在所有者私有的 public 运维表中。实际 PG18 非空、主键、唯一约束、表与列权限、函数正文和不可变触发器逐项校验。状态边只有 privacy_v1 和 authority_v1，可从原步骤的结果摘要沿已验证模块收据走到当前完整摘要；缺边、错误绑定、未知种类、跨计划及未登记漂移不被当成幂等成功。相同数据上的原收据可直接复用，其他已批准步骤造成的变化需要对应状态链。

33个不同检查分阶段取得通过证据，另有独立编译验证；不是一次全仓测试。

实际源 API 执行了专项撤回、素材变更和资料删除，成员撤权通过所有者受控操作产生最小日志。恢复目标使用独立集群、不同角色创建顺序和密码。故障注入确认成员已更新后仍能全部回滚；真实归档保留完整版本，相关三条形象任务 stale，未变团队任务仍 queued、attempts=0；同一素材未撤的独立训练用途保持。最新计划下先撤权再清理、重试及目标 PostgreSQL 重启已验。

原完整业务测试6项失败仍保留：根因是重复撤销归档关联授权，后续依赖断言不能冒充通过。它在失败期间已经建立了第二代计划，所以续验遵守该最新计划，另由新的编译流程验证同计划的相反操作顺序，不删除旧计划或倒退见证头。诊断事务全部回滚，没有重复执行备份恢复。

续验脚本运行时的7项断言已完成，但报告重复使用 result 字段，后来的操作结果覆盖了顶层状态字符串。原报告和实际执行源码已留存并单独绑定；仅修正字段名，没有再执行业务。该重复字段导致的类型检查失败保留，修正后的实际类型结果另行记录。

16项独立编译检查通过：当前工具从包含128的备份直接完成跨集群恢复，生成正确隔离结构固定值，无夹具重设；同计划实际先清理两份账户/匿名资料、再撤下一个成员/一个素材/一份用途，旧步骤沿批准的状态边复用原收据，未变形象任务保持 queued。79份编译、495表和两原密钥在目标PG重启后保持，两业务角色和原配置仍拒绝，未执行旧队列。类型/lint/构建通过；严格关闭10根/13端口及110个捕获创建身份，私有进程/监听为0，未扩大未捕获夹具PID覆盖。主33223四原进程、3310原业务行和两密钥保持，8个已自然过期原登录不复活。文档结构检查的实际结果纳入最终清单。

## 启动与操作

现有工作台继续使用 [本机5174](http://127.0.0.1:5174)，API4301；主33223未重启、切库或替换。

新开发环境按 README 的 pnpm setup:local 与 pnpm dev 启动；请使用独立目录、数据库和端口。对恢复隔离副本，使用私有连接文件及 DATA_DIR 外密钥：

```powershell
pnpm postgres:recovery authority-preview --loader-file <隔离库JSON> --data-dir <隔离恢复目录> --store-dir <日志目录> --key-file <AES密钥> --plan-id <最新计划UUID>
pnpm postgres:recovery authority-apply --loader-file <隔离库JSON> --data-dir <隔离恢复目录> --store-dir <日志目录> --key-file <AES密钥> --plan-id <最新计划UUID> --preview-sha256 <本次完整预览摘要> --confirm-conservative-restriction
```

上述命令属于备份恢复运维，不是让访客或普通员工自行重新授权的产品入口。所有验证使用虚构人员、合成媒体和 mock 供应商；没有真实识别、支付、通知、发布、推流或广告操作。
