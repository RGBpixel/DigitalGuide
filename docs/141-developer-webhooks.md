# 事件回调订阅、签名与持久投递

2026-11-26｜增量141｜T35，R-002、R-009、R-057、R-062、R-120。

平台可以将获授权的制作工程、导出状态变化发送到已登记接收端。管理员在中文界面创建订阅、确认事件范围、排队测试、核对投递及尝试回执，并对失败或不确定结果明确重试。业务改动与出站事件在同一数据库事务中保存，独立派发进程负责发送。

本轮使用虚构组织、合成工程和自有回环HTTP服务。真实HTTPS适配器已实现，其实际接收端接入与生产验收尚未执行；本轮没有真实外部通知、发布、直播、广告、扣费、门禁或音视频设备操作。

## 已实现行为

| 能力 | 当前行为 |
| --- | --- |
| 订阅范围 | 固定组织、一个工作空间、供应商环境与应用环境；事件要求应用仍有对应读取范围 |
| 事件 | `projects.changed`：工程创建或版本、名称、归档变化；`exports.changed`：制作导出创建与状态变化；单独进度更新不产生额外事件 |
| 事件内容 | 不可变的源事件编号、递增序号、发生时间和工程/导出元数据；不包含讲稿、文件、输出结果、私人资料或密钥 |
| 管理确认 | 人员会话、完整组织管理员、CSRF、幂等编号、当前应用和订阅修订、明确勾选确认；部分管理员只核对 |
| 接收端 | 部署管理员的私有注册表限定精确地址和作用空间；界面选择登记名称，不接受任意URL |
| 配置变化 | 地址、密钥或登记信息变化使旧配置指纹失效；重新确认后只处理新事件，旧代次未完成投递取消 |
| 应用撤权 | 停用或变更读取范围原子停用订阅；重新启用应用不会恢复旧订阅或旧投递 |
| 投递身份 | 每条订阅与源事件只有一个投递编号；自动和人工重试保持编号、源事件与完整正文不变 |
| 发送与回执 | 发送前复核当前范围、代次和配置；HTTP结果、正文摘要、开始/结束时间与撤回标记持久保存，已结束尝试不可改写 |
| 不确定结果 | 连接中断或进程终止后保留不确定回执；已开始的HTTP不能撤回，迟到2xx可记入尝试，但不能恢复已取消投递 |
| 重试 | 初始最多5次；首轮退避约5/15/45/135秒，后续封顶300秒；正整数秒`Retry-After`最多采用3600秒；人工增加额度后累计最多20次，不清零次数 |
| 执行约束 | 每个运行时最多4个有效发送租约，租约20秒，HTTP期限3秒；专用进程不领取媒体、通用业务或资金任务 |
| 管理界面 | 订阅、测试排队、状态/原因、尝试回执、人工重试、分页、配置变更、空间切换、旧服务兼容及390px确认框 |

重试具有至少一次投递的语义；有限重试不保证最终送达，源事件可能重复或乱序。接收端应按投递编号持久去重，按源事件序号判断更新顺序。2xx表示HTTP受理，业务是否处理成功由接收端核对。

## 运行方式

先按[开发者接入的独立实例说明](140-developer-access.md)新建开发实例，使用独立数据目录及空闲API/Web端口。主工作台33223的4301/5174、SQLite052及已封存验收根继续保持原状；封存根不作为日常服务重开。

API与派发进程都设置`DEVELOPER_WEBHOOKS_CONFIG_FILE`。注册表和签名密钥必须位于`DATA_DIR`之外，采用绝对路径，不允许链接。注册表示例中的组织、空间和端口需要替换为该独立实例及自有接收服务的实际值：

```json
{
  "version": 1,
  "environment": "mock",
  "appEnv": "development",
  "destinations": [{
    "id": "70000000-0000-4000-8000-000000000001",
    "tenantId": "10000000-0000-4000-8000-000000000001",
    "workspaceId": "20000000-0000-4000-8000-000000000001",
    "name": "本机业务系统接收端",
    "mode": "local_test",
    "url": "http://127.0.0.1:61341/callback",
    "secretFile": "D:\\DigitalGuidePrivate\\receiver.key"

```

`receiver.key`保存随机32字节或更长随机值的base64url文本，允许43—128个字符，不将真实值放入源码或报告。`local_test`仅允许非生产mock环境下字面`127.0.0.1`或`[::1]`的HTTP地址。`https`使用正常证书验证，禁止URL用户信息、查询参数、片段和重定向。

已完成原生独立实例初始化后，在另一个PowerShell终端选择它的worker配置启动派发器。以下目录是新实例的占位示例：

```powershell
$env:DATA_DIR = 'D:\AIProject\DigitalGuide\storage\新建独立原生实例'
$env:DATABASE_DRIVER = 'postgres'
$env:POSTGRES_RUNTIME_CONFIG = "$env:DATA_DIR\worker.json"
$env:POSTGRES_CORE_VALIDATION_ONLY = '1'
$env:RECOVERY_VALIDATION_ONLY = '0'

& 'C:\Program Files\nodejs\node.exe' dist/developer-webhooks.mjs --once
```

`--once`处理一个可用回调；改为`--watch`持续轮询。API使用同一新实例的`api.json`，不能用worker配置启动API。源码入口为`pnpm webhooks:dispatch --once`；编译入口`--help`可独立读取帮助。普通开发不需要启动通用或媒体worker。

真实HTTPS还要求非mock环境、具体业务授权及显式`--confirm-external-delivery`。mock不能用该标志绕过外发限制；缺少配置或真实外发条件会留下受阻结果，不回退为模拟成功。恢复隔离副本拒绝派发。

## 接收端验签

请求头包含`X-DigitalGuide-Delivery`、`X-DigitalGuide-Timestamp`、`X-DigitalGuide-Signature`和与投递编号相同的`Idempotency-Key`。正文封装为`{event, applicationId, subscriptionId}`，应用和订阅编号一并纳入签名。

1. 对收到的原始正文**字节**计算SHA256小写十六进制摘要，不先解析重排JSON。
2. 按UTF8构造`digitalguide-webhook-v1\n<timestamp>\n<deliveryId>\n<bodySHA256>`，其中`\n`是实际换行。
3. 使用密钥文件中的UTF8文本计算HMAC-SHA256；不要先将base64url文本解码为随机字节。请求签名为`v1=<64位小写hex>`。
4. 恒定时间比较签名，校验时间戳在当前时间前后5分钟内，并在接收端业务事务中按投递编号去重。

每次重试刷新签名时间戳，正文和投递编号保持不变。接收端参考校验函数为`packages/enterprise/src/webhook-signature.ts`。OpenAPI 3.1的顶层`webhooks.digitalGuideEvent`给出出站契约；它不是平台可调用的入站URL。
