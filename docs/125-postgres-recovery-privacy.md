# 隔离恢复后的保守个人资料清理

增量125，关联R-009、R-053、R-054、R-058、R-059，T20及完整G2继续。134项需求、38任务、65验收项、26能力组和27项本地verified保持。平台全部制作、直播、发布、PPT、展厅、前台和餐厅范围继续。

## 已接通的实际行为

在[124的签名日志及固定恢复计划](124-postgres-recovery-journal.md)之后，增加`privacy-preview`与`privacy-apply`。预览绑定最新计划、签名见证头、完整恢复库快照、选择规则与人员集合；不会修改业务表或创建永久收据。明确使用预览摘要执行后，在同一事务清除受影响旧人员资料及关联内容、使恢复库全部旧登录失效，并写入不可变收据。未受影响人员资料保留；后续登录及权限仍需重新核对。

最小日志不含最新姓名、偏好或原文，不能据此重建当前资料。此工具采用`personal-data-conservative-v1`：已发生变化、可能失效的旧个人资料按已说明策略保守清理，不复制旧权限或从日志分类猜测本人意愿。原隐私链处理记忆正文/摘要/待办、检索索引、关联访次/对话、导入派生内容与恢复凭证；各条件分支的证据按实际用例判断，不能把调用同一函数当成所有现场条件均已实测。

原生127增加`recovery_conservative`清理原因，仅允许schema所有者在真实隔离恢复库、与该库相符的pending计划下使用。它与本人请求、到期和离开空间的原原因分别记录。正常源实例拒绝冒记保守恢复清理；API及worker不获得内部清理权限。

收据在目标专用`public._dg_native_recovery_privacy_receipts`落库，属于恢复运维元数据。只保留编号、摘要、数量、路由统计与时间，不保存姓名、原文或密钥。所有者、列、7个非空约束、主键/复合唯一、函数及不可变触发器、私有ACL逐项验证；覆盖、删除、TRUNCATE及公开读权限扩张拒绝。同一固定计划与预览重试复用原收据，收据之后的目标数据漂移也会拒绝复用。

## 选择与事务边界

选择规则来自受审查代码，不以日志的privacy/authority标签决定SQL或权限。规则把日志中的原/新主键摘要与恢复行匹配，再沿明确外键关系定位人员；TRUNCATE匹配相应恢复表中的原有记录。覆盖人员、事实/摘要、索引、会话链接/问候、恢复凭证、隐私回执与相关来源、账户/成员、关联消息/访次和餐厅记忆导入/偏好。无法处理的表统计在`unsupported`，不静默当成功完成。

单次最多10000份人员资料，其他行数和容量同时受`--max-rows/--max-bytes/--max-files`限制。更大范围的分批执行和生产规模验证继续。

每次操作重新认证日志包、备份公钥、完整集合、单调见证链及隔离目标，要求已存在的最新固定计划。清理使用READ COMMITTED，在取得目标业务表锁后重新检查基础日志、计划、隔离状态和结构，随后持锁计算快照与执行清理。等待锁期间的实际提交必须进入检查，不能用等待前的旧MVCC快照执行旧预览。数据库和日志资源锁同时覆盖验证与效果，不在两者之间释放。

清理调用原有隐私关联链，并验证已删除状态、正文/索引/链接/凭证清除、旧登录数量与预览相符；提交前强制执行延迟约束。任何失败都回滚资料、登录与本次新建收据。已有完整收据在PG重启后仍可验证复用；本轮未把硬断电或磁盘损坏列为已实测。

恢复完成时固定`check-bool-function-identity-v2`隔离结构摘要。记录和后续核对使用相同search_path、UTC和日期格式，未知函数、约束或权限变化拒绝清理。原默认运行时目录算法、既有v1备份校验均不放宽。
