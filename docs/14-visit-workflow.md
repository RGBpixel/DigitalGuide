# 企业来访闭环：T05

2026-11-18｜M2 建设中｜R-037、R-038、R-039；通用鉴权、幂等、审计与签名约束继续适用。

## 操作路径

打开 http://127.0.0.1:5173/reception，从接待台创建终端并开始匿名接待。访客可以在终端下方自愿填写姓名/昵称、单位、指定受访人、事由和可选预约引用。保存草稿后先展示资料核对，再由访客勾选本次用途说明并点击“确认登记并发送模拟通知”。输入属于本人自述，不升级员工身份，也不创建人脸、声纹或长期人员档案。

品牌与接待演示工作空间的虚构受访人是林知和陈墨，分别关联演示管理员与内容编辑账号；青禾餐饮工作空间使用沈禾。没有发布的受访人、未知受访人或不可用账号进入人工处理。访客端不提供员工名录、手机号、日程或内部备注。

指定接待人登录后进入“我的接待请求”，才能同意或暂不接待。即使是前台管理员，也不能代替另一名接待人表示同意。管理员在“来访记录”查看授权工作空间内的记录，可以转人工、取消或结束人工处理记录。普通编辑只能处理自己被指定的请求，只读账号没有写入权限。

同意接待后，访客只看到允许公开的指引：前台等候、一层等候区或由工作人员陪同到演示会议室。内部备注仅对前台管理和指定接待人开放。访客可明确确认到达并结束来访，也可取消；取消不会伪称已撤回渠道已经接受的消息。

## 状态与确认

保存为 awaiting_confirmation，资料修改递增版本。确认凭证绑定会话、focusVersion、登记版本、内容哈希、指定收件账号、通知用途与到期时间；确认期限最多 2 分钟且不超过访客会话有效期。旧版本、过期、伪造或服务对象变化后的确认会被拒绝。用途说明版本 visit-v1 与确认时间保存到来访记录。

确认后的资料不能直接覆盖。通知创建与 outbox 同事务提交，同一来访只能有一条通知投递记录，不因换幂等键而重复提交。并发通知按租户限制为 1，日限额取组织限额与 100 的较小值；本地模拟不产生真实费用，真实单价仍为未知。

通知状态分别为 queued、submitting、submitted、delivered、acknowledged、failed、unknown、cancelled。submitted 只表示模拟渠道接受请求；送达或已读均不等于员工同意。只有经过登录、对象授权和版本检查的指定接待人操作，才产生 accepted 或 declined。完成与取消保存时间，已确认记录不会因页面刷新、服务重启或终端结束而消失。

等候接待回复的初始时限为 60 秒，由 API 和 worker 依据服务端 UTC 执行。渠道失败、结果未知、无人响应或上下文失效转 escalated，暂停活动终端的自动回复并取消旧播放状态。访客的旧确认不能跨人工接管继续使用，后续由前台明确处理。

003-visits.sql 添加来访、受访人发布、投递和模拟回执数据；004-visit-confirmed-target.sql 固定确认时的收件账号。配置调整不会将旧请求、详情或内部备注交给新账号。旧开发记录只有已有投递的收件账号可用于回填，没有可靠快照的未发送确认保持未分配，需要人工复核，避免猜测接待人。

## 通知与回执

NotificationProvider 定义发送与查询边界。当前 mock-notification 把提交回执持久保存，仅使用来访引用、指定收件账号和接待必要资料，不发送整段会话。投递使用租约令牌；失去租约的旧 worker 不能覆盖结果。重启后对未结算提交先查已有回执，不直接重发；无法确定结果就记录 unknown 并转人工。

模拟回调使用独立用途派生的服务端 HMAC-SHA256 签名、毫秒时间戳和 5 分钟窗口。事件 ID 与内容哈希用于去重和防冲突，迟到失败不会把送达/已确认状态降级。签名密钥不下发前端或写入普通日志；模拟回执按钮由已授权管理员触发，并在服务端走同一验签逻辑。

接口包含：访客路径 /guest/sessions/:id/visit 及 confirm、notify、control；管理路径 /visits；本人收件箱 /visits/inbox；指定接待人的 /visits/:id/respond；前台 control 与显式 mock-receipt、mock-notification。/webhooks/mock-notification 仅接受已验证签名的模拟回调，production 或非 mock 环境不开放模拟回执。

公开和内部响应分别使用 visitSchema 与 internalVisitSchema，保持内部备注、接待人授权和确认快照隔离。对应输入、响应及签名头契约通过 pnpm api:spec 生成 [OpenAPI](api/openapi.json)。
