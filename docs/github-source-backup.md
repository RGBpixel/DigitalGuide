## 包含与排除

Git 保存 `apps/`、`packages/`、`migrations/`、`tests/`、`scripts/`、设计文档及配置示例。`.gitattributes` 保留原始文件字节，避免换行转换破坏数据库迁移和恢复规则的 SHA256 校验。

下列内容保留在原电脑，不上传：

- `storage/` 中的数据库、演示副本、媒体对象、服务端密钥、账号配置、下载的模型和工具。
- `node_modules/`、`.pnpm-store/`、`dist/`、测试日志、临时文件和生成的交付文件。
- `docs/evidence/` 中的原始验收报告、截图、数据库副本、编译副本、源文件快照及进程身份记录；此目录只提交说明和测试需要的空目录占位。
- 私有环境文件、私钥文件及名称带 `.private.` 的本地文件。`.env.example` 仅提供配置字段，不包含真实凭据。

源码仓库不能代替业务数据备份。需要搬迁现有工程、媒体或已保存的业务记录时，应另外备份并传输 `storage/` 与对应私有密钥；不把这些文件加入 Git。历史文档中的本地证据链接可能只在原电脑上可用，历史续验脚本需要相应原始现场，不能用空目录替代验收证据。

## 在新电脑启动

准备项目要求的 Node.js 24.x 与 pnpm 版本后，在新的项目目录运行：

```powershell
pnpm install
pnpm setup:local
pnpm setup:media
pnpm dev
```

默认网页为 `http://127.0.0.1:5173`，API 为 `http://127.0.0.1:4300`。`setup:local` 创建新的本地数据和虚构演示资料，不会从 Git 恢复原电脑的业务数据库或媒体。已有数据目录应先核对 [本地开发说明](12-local-development.md) 与 [PLAN.md](../PLAN.md)，避免把历史主库当作新环境直接升级。

下载的模型、摄像头、真实形象与声音克隆、第三方业务账号、直播发布、支付和现场声纹抗噪等条件需要另行配置和验收。界面中的模拟能力不作为真实供应商或现场验收证据。
