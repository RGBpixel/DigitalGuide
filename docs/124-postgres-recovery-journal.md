## 当前交付与边界

原生PostgreSQL应用的业务变化与最小日志在同一事务提交，回滚不会留下孤立日志。新增在线日志导出与隔离恢复副本的差异计划。计划固定为pending，只列出需核对的变化；尚不执行选择性删除、撤权、业务补偿或启用。旧备份中的个人资料可能仍在隔离副本里，不能称为“已完成恢复后删除传播”。

## 同事务捕获

捕获覆盖原生业务表的INSERT、UPDATE、DELETE和TRUNCATE；迁移表、运行控制与日志自身有明确排除清单。启动初始化固定覆盖表、主键列及触发器状态的摘要；导出与恢复核对重新验证覆盖，缺失捕获不当成功。API和worker无读取日志、修改信任根或安装捕获函数的权限。日志、信任根、计划拒绝覆盖、删除与TRUNCATE。

单条记录仅含随机事件编号、实例与流编号、表名、操作、主键摘要、可用的版本及事务号、时间和用途路由提示。主键摘要绑定流和表；不记录姓名、偏好正文、对话、令牌或密钥。privacy/authority/business仅作待处理分类，不能凭分类自动删除、恢复授权或执行资金操作。

不使用“最大事件号”作为已提交进度。业务事务不竞争全局序列行锁。每次导出读取可见的完整已提交集合，按事件UUID固定排序，核对既有见证集合全部仍在，包含先开始、后提交的事务。

## 外置签名与加密日志

Ed25519私钥初始化在DATA_DIR父目录的`.dg-native-journal-<runtimeId>.pem`，不随DATA_DIR备份；公钥、流、覆盖摘要与备份时日志集合检查点进入认证备份。独立AES密钥和签名私钥均不得位于DATA_DIR或日志库中。此实现使用本地私有文件，不声称HSM或生产KMS。

导出使用可在线执行的只读一致快照，核对源身份、迁移、目录权限和覆盖，不停止正常API。签名清单绑定实例、schema、流、覆盖、代数、前一见证头摘要、完整集合摘要和文件清单。AES-256-GCM加密、认证回读后，独占发布不可变密文，再原子替换`head.json`。相同集合复用原见证，但仍认证旧包，错误AES密钥不能经复用路径成功。

历史头在其已发布之后、下一代发布之前固定到`heads/<generation>.json`，避免失败的新发布提前占用未来代数。日志资源使用现有运维锁，不能并行覆盖或自动接管死亡锁；中断现场需要检查后按准确operationId明确解锁。源DATA_DIR不因日志导出进入停机维护锁。

见证模式明确为`local-offline-file`，`productionFreshnessProven:false`。本地目录、签名或完整链不能证明灾难发生前最后一条已确认变化均已复制；生产仍需独立持久见证、复制回执和新鲜度策略。

## 隔离恢复核对

恢复只进入[123规定的独立空库及原绝对DATA_DIR](123-postgres-recovery.md)。目录策略和数据库恢复控制共同绑定备份编号、归档摘要、实例、schema及日志检查点。原API/worker配置保持隔离桩，数据库CONNECT和schema USAGE均拒绝；不会恢复旧登录、执行旧任务或自动发布。

`journal-plan`验证目标隔离、备份固定公钥、原始日志集合、完整见证链及认证密文，再暂存源完整集合核对原始记录。已见过的新代不能降级，同代不同头、跳代/缺失历史、原始记录缺失，以及此前已核对集合被移除或改写均拒绝。新计划按表、路由分类、操作、事件数和主键摘要数量聚合，不保存正文；收据落库、不可变、幂等，重启后继续复用。`changesApplied:false`与`activationAllowed:false`保持。

本轮跨集群检查发现同名重载函数的目录查询顺序会不同。新备份使用`check-bool-function-identity-v2`：保留受限CHECK分组规范化，并按函数签名固定定义顺序，权限同样绑定对应签名。原运行时目录算法、`check-bool-v1`及旧原始摘要规则保持，不把旧备份自动改标为新算法。权限在两个重载间互换仍会拒绝。原失败备份和失败副本保留；未重复其已提交的pg_restore。

## 本地运行

默认继续使用已有工作台：`http://127.0.0.1:5174`。本增量是运维命令，没有新增用户界面或OpenAPI端点。

在仓库使用`pnpm postgres:recovery --help`查看严格参数；可独立打包运行`node dist/postgres-recovery.mjs --help`。只使用私有连接JSON和密钥文件，不在命令中传密码。

```powershell
pnpm postgres:recovery journal-export --config-file <私有api.json> --loader-file <独立运维连接JSON> --store-dir <DATA_DIR外日志目录> --key-file <独立AES密钥>
pnpm postgres:recovery journal-plan --loader-file <隔离恢复库连接JSON> --data-dir <隔离恢复目录> --store-dir <外置日志目录> --key-file <同一日志AES密钥>
```

`journal-export`默认定位初始化生成的外置签名私钥，也可显式指定`--signer-file`。容量参数`--max-bytes/--max-files/--max-rows`限制导出、解码及核对；错误返回中文原因和稳定错误码，不打印原数据。查看或明确解锁日志资源：`inspect|unlock --data-dir <日志目录>/<streamId>/head.json`；unlock另需`--operation-id`，活进程锁不能强制解除。
