# 员工口信、日历与提醒：T07

2026-11-18｜M2 本地实现｜R-043、R-044。整体 G1/G2 仍在建设。

## 使用路径

打开 http://127.0.0.1:5173/office，或选择左侧“消息与日历”。页面包含“我的收件箱”“我发出的口信”“会议与提醒”。演示账号均为虚构；林知和陈墨可创建口信与会议，只读成员可读取和确认自己的收件、回应本人会议邀请。

收件、发件、日历与详情按租户、工作空间、当前运行环境及对象归属校验。管理员不能代替收件人确认，也不能默认查看其他人的口信或未参与的会议。匿名访客、登记为员工的普通 Person、人脸/声纹候选都没有员工消息权限。成员选择仅使用当前工作空间的最小账号目录，不提供手机号、邮箱或他人日程。

## 口信流程

填写指定收信人、题目、正文、保密级别、渠道、转达时间和有效期，先保存草稿。核对后明确确认当前版本，才进入转达队列。发信人始终取自服务端登录身份，不能由表单冒充其他同事。

草稿可修改，修改后旧确认无效。确认勾选绑定所见对象版本，轮询更新不能沿用旧勾选。已经确认的口信不能覆盖内容；需要修改时撤回后重新创建。留空转达时间表示确认后尽快处理，指定未来时间表示定时转达。有效期默认七天，服务端限制在未来 90 天内且晚于转达时间；每个发信人每天最多创建 100 份草稿。

数字人式转达在收件卡片中明确写为“某同事托我转达”，不冒充发信人作承诺。本地撤回会停止尚未执行的任务、清理本地正文和旧提醒；已经被外部渠道接受的消息不能因此宣称已从外部撤回。

保密程度记录为 private 或 public。public 表示允许在核对身份后的受控场景转述，不产生匿名公开访问权。本批公共画面预览统一使用通用提示，后续由明确的员工身份/场景绑定接入数字人播报。

## 回执的含义

本地收件箱与可选模拟渠道分别记账：

| 字段/状态 | 含义 |
| --- | --- |
| pending / queued | 已确认，等待转达时间或 worker |
| unread / local | 已写入本地本人收件箱，尚未读取 |
| submitted_mock | 模拟渠道接受请求，没有发送真实消息 |
| read | 收件人明确标记已读 |
| acknowledged | 收件人明确确认收到内容 |
| failed / unknown | 模拟渠道失败或结果无法确定，本地收件仍可查看 |
| withdrawn / expired | 内容已撤销或到期，不再显示旧正文 |

已读、本人确认和会议同意参加分别记录；渠道提交成功不自动产生任何一种本人确认。私密正文只在本人登录后的页面可读。公共提示接口只返回“您有待查看消息，请在个人终端登录查看”，不含题目、正文、发信人、收件人、桌位或会议安排。

接口写入只返回标识、版本和状态，不在幂等响应中复制正文；页面随后读取当前状态。撤回、到期与改期会使旧快照失效，不让旧请求重放重新公开已经清理的内容。

## 本地会议与提醒

本地日历是本批会议的事实源，不从模型聊天推断开会，也不假装读取了企业微信、钉钉、飞书或其他企业日历。创建时明确核对题目、说明、地点、开始/结束、参与者与提醒设置。

时间在 API 和数据库规范为 UTC，页面按指定时区展示。当前表单按本机时区输入并标明时区；服务端验证 IANA 时区、结束晚于开始、未来一年内开始且持续不超过七天。每场含组织者最多 20 人，每位组织者每天最多创建 50 场；参与者必须在同一工作空间。

组织者可以修改或取消，参与者仅回应自己的邀请。改期递增内容版本，撤销原邀请/提醒，再产生新版本更新及提醒，旧版回应被拒绝。移除的参与者只能收到无新会议信息的范围变更提示，不能读取新题目、说明或地点。取消后不再转达旧会议提醒；必要的取消通知仍进入本地收件箱。

提醒支持开始前 0、5、10、15、30、60 分钟。已过提醒点但会议尚未结束的任务尽快处理，记录实际状态，不承诺硬实时送达。会议结束后旧提醒失效；结束 30 天后清理题目、说明和地点，保留最小状态记录。

收件箱是被动查看，不在公共扬声器、系统通知或其他应用自动弹出私密内容。主动语音问候、员工视觉识别与数字人现场播报仍遵循 T26/T37 及既有免打扰规则，不能以本页可用冒充真实识别已接通。

## 持久化与提供商边界

006-office.sql 添加口信、会议、参与者、通知队列及模拟回执表。通知唯一键包含来源、内容版本、接收人和类型；确认与队列写入同事务提交，避免重复转达。worker 持有 15 秒租约，同租户同环境一次处理一个通知；崩溃恢复对已开始的提交先查询持久回执，不直接重发。

渠道返回未知时保留 unknown，不静默模拟成功或自动重发。旧租约、已撤回来源、变更后的内容版本和已移出工作空间的账号都不能使旧通知恢复可读。模拟提供商只持久保存哈希和回执引用，普通审计与 outbox 不复制正文。

local 渠道是实际本地数据库收件，mock 渠道是显式测试适配器。sandbox/live 或 production 不接受模拟渠道配置。当前没有真实外部通知、日历同步、短信、邮件、桌面系统通知或发送到其他应用。本批不开放可伪造的 HTTP 渠道回调；未来真实回调继续要求验签、时间窗口、幂等和版本校验。

口信按各自有效期清理，会议按其结束后 30 天清理。业务记录与本人偏好是不同用途，不因删除偏好而擅自销毁必要业务状态。生产备份、加密、管理员治理和外部渠道删除仍由 M6/真实接入另行验证。

## API 与验证

共享输入/输出契约位于 packages/contracts/src/office.ts，生成于 [OpenAPI](api/openapi.json)。

- 本人发件：/office/relays，详情及 edit、send、cancel；scenario 仅供演示管理员设置尚未确认的模拟测试场景。
- 本人收件：/office/inbox、/office/notifications/:id，control 仅收件人能标记已读或确认。
- 本人通用提示：/office/public-notice，仍需本人登录，不向匿名访客映射员工身份。
- 会议：/office/calendar，详情及 update、cancel、respond。
- 成员：/office/members，仅具备创建员工事务权限的账号可查最小目录。

实现和实际检查见 [T07 验证记录](evidence/T07/verification.json)。专项测试覆盖权限与私密投影、确认版本、定时、未知结果、租约恢复、撤回竞争、成员失效、会议回应/改期/取消、移除参与者和保留期。浏览器分别使用独立员工上下文验证口信与会议闭环，保存桌面和手机截图。

真实企业消息及外部日历需要已授权的测试应用、服务端凭据、成员映射、允许收件范围和实际回执。R-043/R-044 的真实部分保留 waiting_external，不把本地实现当作完整平台或 G2 验收。
